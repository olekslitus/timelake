# Table properties

A table’s contract and maintenance policy live in Iceberg table properties under the `timelake.` prefix. Other engines ignore them. Set them at creation with `--prop key=value` (CLI) or `properties={…}` (Python); the contract flags (`--time-column`, `--series-key`, `--chunk`, `--retention`, `--no-dedup`) set the first five.

| Property | Default | Meaning |
| --- | --- | --- |
| `timelake.time-column` | (none) | The time column. Its presence makes the table a time-series table. |
| `timelake.series-key` | (none) | Comma-separated series key columns. |
| `timelake.chunk-interval` | day | Partition size: hour, day, or month. |
| `timelake.dedup` | true with a series key, else false | Rows with the same (series, time) count once; the latest write wins. Applied within an append, by the Timelake reader, and by compaction. |
| `timelake.retention` | forever | Drop partitions that end before now minus this duration, e.g. 90d. |
| `timelake.auto-maintain` | true | Run size-tiered compaction, retention, and snapshot expiry inline after appends. |
| `timelake.compact-min-files` | 8 | Inline compaction merges a size tier of a partition once it has this many files. |
| `timelake.target-file-size-bytes` | 268435456 (256 MiB) | Size at which compaction output and writes roll to a new file. |
| `timelake.row-group-rows` | 1048576 | Parquet row group size. Page indexes keep single-series reads selective inside large row groups. |
| `timelake.snapshot-retention` | 1h | Expire snapshots older than this… |
| `timelake.min-snapshots` | 5 | …but always keep at least this many, |
| `timelake.max-snapshots` | 100 | and never keep more than this many (older ones expire even if younger than the retention). |
| `timelake.format-version` | `0.2.0` for new tables; absent means `0.1.0` | The [table format](/docs/upgrading#table-format), a semantic version. Timelake refuses tables of a newer format it can't handle; `timelake upgrade` brings a table to the current format. |
| `timelake.keep-snapshots-until` | (none) | No snapshot expires before this time, in milliseconds since the epoch. `upgrade` sets it so the upgrade can be rolled back. |
| `timelake.head-format` | arrow | Format of the head object (`metadata/timelake-head`): `arrow`, `json`, a registered codec, or `none` for no head. See [Architecture](/docs/architecture#head-object). |
| `timelake.head-inline-bytes` | 1048576 (1 MiB) | Room in the head for the last-value index, then the Parquet footers of the newest files. What doesn’t fit is read separately. |

Durations are a number and a unit: `s`, `m` (minutes), `h`, `d`, `w` or `y`, or the long forms (`90 days`, `2 weeks`). Examples: `30m`, `36h`, `90d`, `1y`.

## Iceberg properties set at creation

- `write.format.default = parquet` and `write.parquet.compression-codec = zstd`
- `write.metadata.previous-versions-max = 20`: keeps `metadata.json`, which every query reads, small. Older metadata files are deleted by snapshot expiry.

## Schema

Arrow types are mapped to the closest lossless Iceberg type when a table is created:

- 8- and 16-bit integers become `int`; `UInt32` becomes `long`; `UInt64` is rejected.
- Timestamps of any unit are stored in microseconds; time-zone-aware timestamps become `timestamptz` (UTC).
- Dictionary-encoded columns use their value type; large and view string and binary types become string and binary.
- The time column is NOT NULL, and a text time column is stored as a UTC timestamp.

Schema evolution isn’t supported yet: the schema is fixed when the table is created.
