# Development

How to build, test and run each part of the repository. For what each part is, see the [Codebase tour](/docs/codebase).

## Tools to install

| Tool | Needed for | Install |
| --- | --- | --- |
| Rust (rustup) | Everything in `crates/` | `curl https://sh.rustup.rs -sSf \| sh`. The version (1.94) is pinned in `rust-toolchain.toml`; rustup installs it on first use. |
| uv | Python package and benchmarks | `curl -LsSf https://astral.sh/uv/install.sh \| sh` |
| Bun | Website and TypeScript client | `curl -fsSL https://bun.sh/install \| bash` |
| Go | The benchmark proxy only | `brew install go` |
| LLVM, wasm-bindgen | Rebuilding the WASM reader only | `brew install llvm`, `rustup target add wasm32-unknown-unknown`, `cargo install wasm-bindgen-cli` |

## Rust: engine and CLI

```bash
cargo build --release -p timelake-cli        # → target/release/timelake
cargo test --workspace                          # tests
cargo clippy --workspace --all-targets          # lints
cargo fmt --all                                 # formatting
```

The Cargo workspace (root `Cargo.toml`) holds `timelake`, `timelake-format`, `timelake-cli` and `timelake-py`, with one `Cargo.lock` and one `target/`. `timelake-wasm` is built separately for WebAssembly (see below).

Try the CLI on a throwaway warehouse:

```bash
export TIMELAKE_WAREHOUSE=/tmp/tl-dev
target/release/timelake import iot.readings readings.csv --time-column time --series-key device_id
target/release/timelake sql "SELECT count(*) FROM iot.readings"
```

## Python package

```bash
uv sync                                    # at the repo root: builds the package into ./.venv
uv run pytest crates/timelake-py/tests
```

The root `pyproject.toml` is a uv workspace with two members: the package (`crates/timelake-py`) and the benchmarks (`bench`). `uv sync` and `uv run` rebuild the native module with maturin whenever Rust sources change. The Python files live in `python/timelake`; the native part is imported as `timelake._timelake`.

## WASM reader and TypeScript client

```bash
bun install                                         # at the repo root (bun workspace)
cd packages/timelake-client
bun run build:wasm                                  # after changing crates/timelake-wasm
bun run typecheck
```

The client tests compare its answers with the CLI's, on a demo warehouse served locally:

```bash
cargo build --release -p timelake-cli
scripts/build-demo-warehouse.sh                     # needs the TSBS data in bench/data
bun scripts/serve-range.mjs bench/data/demo-site 4100 &
(cd packages/timelake-client && bun test)
```

## Website

```bash
bun install                       # at the repo root
cd dashboard
bun run dev                       # http://127.0.0.1:3000
bun run lint
bunx tsc --noEmit                 # type check
bun run build                     # production build, as Vercel runs it
```

Docs pages are plain React files in `dashboard/app/(site)/docs/<page>/page.tsx`; the sidebar order is in `dashboard/lib/docs-nav.ts`. After re-running benchmarks, copy the results the site uses with `bun run sync-results`.

The Explorer runs the local CLI against `TIMELAKE_WAREHOUSE` (default: the v0 benchmark tables in `bench/data`). See `dashboard/README.md` for its settings and the hosted mode.

## Benchmarks

```bash
uv sync                                       # at the repo root; the same environment as above
cd bench && (cd tools/s3proxy && go build -o ../../.bin/s3proxy .)
uv run python run.py --suite tsbs_iot --engine duckdb --layout sorted
```

Then follow `bench/README.md` (query suites and data), `bench/v0/README.md` (the v0 comparison) or `bench/infra/README.md` (AWS). Benchmark data lives in `bench/data` (git-ignored, several GB).

## Code style

- **Rust:** `rustfmt` and `clippy`; errors with `thiserror` in libraries and `anyhow` in the CLI.
- **TypeScript:** no semicolons, double quotes, strict TypeScript.
- **Comments:** explain why, not what. Public items get a doc comment.
- **Commits:** short imperative subject with the area first, such as `bench: …`, `Site: …` or `SPEC: …`.

## Continuous integration

Vercel builds and deploys the website on every push to `main`. There are no automated tests or lint checks on pushes yet; run the commands above before pushing. Setting up CI and pre-commit hooks is the next step on the roadmap.
