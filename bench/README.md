# timelake-bench

Benchmarks for SPEC.md §17. Three sets live here:

| Set | What it answers | How to run | Results |
|---|---|---|---|
| **Phase 0 baseline** (this file) | How fast are the engines and layouts Timelake builds on and competes with, on local disk and S3-compatible storage? | below | [`results/BASELINE.md`](results/BASELINE.md), [`OBJECT_STORAGE.md`](results/OBJECT_STORAGE.md), [`VORTEX.md`](results/VORTEX.md) |
| **v0 comparison** | The same IoT stream written into Timelake, naive Iceberg (the S3 Tables pattern) and Lance: ingest, then queries before and after maintenance | [`v0/README.md`](v0/README.md) | [`results/V0.md`](results/V0.md) (RustFS), [`results/TIMESCALE.md`](results/TIMESCALE.md) |
| **Real AWS** | Phase 0 and v0 on AWS S3 and real S3 Tables | [`infra/README.md`](infra/README.md), `run_aws.sh` | [`results/S3.md`](results/S3.md) |

Shared pieces: `run.py` (runs one suite on one engine), `queries/`, `scripts/` (data preparation), `tools/s3proxy` (counts S3 requests; adds latency or signs for AWS), `compare_*.py` and `summarize.py` (tables from results).

## Suites
| Suite | Data | Queries |
|---|---|---|
| `tsbs_iot` | TSBS IoT, 500 trucks × 3 days at 10 s (11.7M readings + 11.7M diagnostics, ~10% missing points by design), seed 123 | 12 TSBS IoT queries ported to portable SQL (`queries/tsbs_iot/queries.sql`, porting rules in its header) |
| `tpch` | TPC-H SF10 as Parquet (zstd), generated by DuckDB `dbgen` | 22 TPC-H queries from DuckDB's `tpch` extension |
| `clickbench` | ClickBench `hits` **10% subset** (partitions 0–9 of 100, ~10M rows) | 43 official ClickBench queries, using each engine's own SQL from the ClickBench repo |

## Engines
- DuckDB, DataFusion, and Polars (Python packages; versions recorded in every result)
- `duckdb-iceberg`: DuckDB reading the TSBS data as **Iceberg** tables (written by PyIceberg, partitioned by `day(time)`, sorted by `(tags_id, time)`)
- `timescaledb`: TSBS's own loader and query runner against TimescaleDB in a throwaway Docker container (`scripts/timescaledb.sh`). TSBS's loader needed a one-line patch for TimescaleDB ≥ 2.14 (it still passed the removed `replication_factor` argument).

## Method
- Each query runs in a fresh subprocess: one first run, then 3 repeat runs. **Reported = best repeat run.**
- Every run fully materializes the result as Arrow.
- Row counts are recorded and compared across engines.
- "First run" is not a cold-cache run: the OS page cache stays warm (dropping it needs root on macOS).
- Engines run strictly one at a time, with default settings and all cores.
- TimescaleDB reports the **median over 20 randomized instances** per query type: TSBS randomizes the fleet and time window per instance, while the lake port uses fixed parameters.

## Object storage (RustFS + latency proxy)
The same suites run against S3-compatible storage with `--storage s3`:
- **RustFS 1.0** (Apache-2.0, MinIO's successor in practice) runs in a throwaway container.
- **`tools/s3proxy`** sits in front of it and adds a fixed **time-to-first-byte per request** (default 20 ms, roughly S3 standard in-region) without throttling bandwidth. It also counts requests and response bytes per run.
- Results record wall time, plus `requests` and `bytes` for every run.

```bash
docker volume create timelake-bench-rustfs
docker run -d --name timelake-bench-rustfs -p 59000:9000 -v timelake-bench-rustfs:/data \
  -e RUSTFS_ACCESS_KEY=benchkey -e RUSTFS_SECRET_KEY=benchsecret123 rustfs/rustfs:latest
(cd tools/s3proxy && go build -o ../../.bin/s3proxy .)
.bin/s3proxy -listen :59100 -upstream localhost:59000 -admin :59101 -ttfb 0ms &
# upload: data/{tpch,clickbench,tsbs/parquet} -> s3://bench/... ; Iceberg: scripts/tsbs_to_iceberg.py s3
./run_s3.sh                                                   # 0 ms and 20 ms passes
.venv/bin/python summarize.py --metric=first tsbs_iot.rustfs-20ms
# cleanup
docker rm -f timelake-bench-rustfs && docker volume rm timelake-bench-rustfs
```

## Reproduce
```bash
cd bench
UV_PROJECT_ENVIRONMENT=.venv uv sync
GOBIN=$PWD/.bin go install github.com/timescale/tsbs/cmd/...@latest   # then apply the loader patch (see above)
# data (see commands in BASELINE.md "Data generation")
./run_all.sh                    # DuckDB / DataFusion / Polars / DuckDB+Iceberg
./scripts/timescaledb.sh        # TimescaleDB (Docker)
.venv/bin/python summarize.py   # markdown tables
```
Data lives in `bench/data/` (gitignored, ~4 GB). Delete it with `rm -rf bench/data`.
